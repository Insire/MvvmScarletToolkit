MvvmScarletToolkit provides classes to speed up the MVVM development process for XAML-based applications using the viewmodel first approach. It supports WPF and Avalonia.

Features

Each package has its own readme with the full list of what it contains.
  • MvvmScarletToolkit.Commands: fluent interface to build task based ICommands with cancellation, single execution and busy state notifications
  • MvvmScarletToolkit.Observables: viewmodel base classes, threadsafe busy state, localization, change tracking, paging and navigation
  • MvvmScarletToolkit.Wpf: behaviors, converters as markup extensions, DataGrid extensions, FileSystemBrowser with file and folder dialogs, virtualizing panels, HtmlTextBlock, selectable text and toast notifications
  • MvvmScarletToolkit.Avalonia: Avalonia implementations of the toolkit services, async image loading and virtualizing panels
  • MvvmScarletToolkit.ImageLoading: loading and caching images from remote resources
  • MvvmScarletToolkit.Mediator: simple mediator with requests and notifications
  • MvvmScarletToolkit: extension methods used across the toolkit
  • MvvmScarletToolkit.Abstractions: interfaces shared by the rest of the toolkit

Getting Started

Install

Install the package for your UI framework. It brings in the commands, viewmodel base classes and abstractions. For WPF: 
dotnet add package MvvmScarletToolkit.Wpf
For Avalonia: 
dotnet add package MvvmScarletToolkit.Avalonia
The current NuGet release (5.0.96) targets .NET 8 and 9, and is built against Avalonia 11. The source in this repository targets .NET 8 and 10, and Avalonia 12. Pre-release packages are available on GitHub. GitHub requires a personal access token to restore from its NuGet feed.

Create a viewmodel

Derive from ViewModelBase and create commands through the IScarletCommandBuilder passed to the constructor: 
using MvvmScarletToolkit;
using MvvmScarletToolkit.Observables;
using System.Windows.Input;

public sealed class CounterViewModel : ViewModelBase
{
    private int _count;
    public int Count
    {
        get { return _count; }
        private set { SetProperty(ref _count, value); }
    }

    public ICommand IncrementCommand { get; }

    public CounterViewModel(IScarletCommandBuilder commandBuilder)
        : base(commandBuilder)
    {
        IncrementCommand = commandBuilder
            .Create(Increment)
            .WithSingleExecution() // only one execution at a time
            .WithBusyNotification(BusyStack) // sets IsBusy while running
            .WithAsyncCancellation() // adds cancellation support
            .Build();
    }

    private async Task Increment(CancellationToken token)
    {
        await Task.Delay(500, token);
        await Dispatcher.Invoke(() => Count++);
    }
}
For viewmodels that load their content, derive from BusinessViewModelBase or BusinessViewModelListBase<T> instead. They provide LoadCommand, RefreshCommand and UnloadCommand, and unload when the application exits.

Create the viewmodel at startup

ScarletCommandBuilder.Default provides the services for the current UI framework. Use it once the application has started, because it depends on the running application. It can also be registered in a DI container as a singleton. For WPF, in App.xaml.cs (remove StartupUri from App.xaml): 
protected override void OnStartup(StartupEventArgs e)
{
    base.OnStartup(e);

    var window = new MainWindow
    {
        DataContext = new CounterViewModel(ScarletCommandBuilder.Default),
    };

    window.Show();
}
For Avalonia, in App.axaml.cs: 
public override void OnFrameworkInitializationCompleted()
{
    if (ApplicationLifetime is IClassicDesktopStyleApplicationLifetime desktop)
    {
        desktop.MainWindow = new MainWindow
        {
            DataContext = new CounterViewModel(ScarletCommandBuilder.Default),
        };
    }

    base.OnFrameworkInitializationCompleted();
}

Bind the view

<StackPanel>
    <TextBlock Text="{Binding Count}" />
    <Button Command="{Binding IncrementCommand}" Content="Increment" />
    <ProgressBar IsIndeterminate="{Binding IsBusy}" />
</StackPanel>
The toolkit's XAML types share a single namespace in both frameworks. The WPF package has the larger set of converters and behaviors: 
xmlns:mvvm="http://SoftThorn.MvvmScarletToolkit.com/winfx/xaml/shared"

Explore the samples

The samples show these features in working applications. Requires the .NET 10 SDK: 
git clone https://github.com/Insire/MvvmScarletToolkit.git
cd MvvmScarletToolkit
Run the WPF samples (Windows only): 
dotnet run --project samples/MvvmScarletToolkit.Wpf.Samples
Run the Avalonia samples: 
dotnet run --project samples/MvvmScarletToolkit.Avalonia.Samples

Build Requirements

This repository requires the .NET 10 SDK, as configured in global.json. The easiest way to get everything is Visual Studio 2026 or newer, which prompts you to install any missing components when you open the slnx file. Otherwise, you need:
  • Windows 10 or newer, or Linux (building only: the WPF projects and their tests and samples only run on Windows)
  • .NET 10 SDK
  • .NET 8 Runtime to run the tests for that target
  • Visual Studio Code with the C# Dev Kit provided by Microsoft
  • git
Build the solution: 
dotnet build MvvmScarletToolkit.slnx
Run the tests: 
dotnet test --solution MvvmScarletToolkit.slnx
